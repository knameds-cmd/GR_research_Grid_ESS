## 0. 이 문서를 쓰는 법

- 작업은 **T0 → T1 → … → T9** 순서입니다. 앞 작업이 끝나기 전에 다음 작업을 시작하지 않습니다.

## 2. 모형 명세

### 2.1 집합과 입력

- 구역 z (3 또는 5개, T3), 시간 t = 1…8760 (2030년, 1시간)
- 경계 l: 구역을 잇는 선. **방사형 사슬**(예: 북부 스코틀랜드 — 남부 스코틀랜드 — 잉글랜드·웨일스)이면 경계 조류는 구역 순위치로 유일하게 정해집니다. 5구역도 사슬 구조를 유지하는 것을 기본으로 합니다(고리가 생기면 조류가 유일하지 않아 S1b 정의가 흔들림).
- 발전기 g: 구역, 용량, 한계비용(연료·탄소 FES 가정), 가용 시계열(풍력·태양광)
- 저장 s: 구역, 충·방전 출력, 저장량, 충·방전 효율. **Window 1 잠정 16건**은 실제 위치·크기로, 나머지 저장(단주기 배터리, 기존 양수)은 FES 값으로
- 수요 D(z, t), 정전 비용 VoLL(큰 값, spec.yaml)
- 경계 한도 F(l) (2030년, ETYS 등 출처를 적음)

### 2.2 1단계: 전국 시장 (구리판)

```
min  Σ_t Σ_g c_g · p[g,t]  +  VoLL · Σ_t shed[t]
s.t. Σ_g p[g,t] + Σ_s (d[s,t] − ch[s,t]) + shed[t] = Σ_z D[z,t]        ∀t   (쌍대 = 전국 가격 λ[t])
     0 ≤ p[g,t] ≤ cap_g · avail[g,t]
     0 ≤ ch[s,t] ≤ Pch_s,  0 ≤ d[s,t] ≤ Pdis_s
     e[s,t] = e[s,t−1] + η_ch·ch[s,t] − d[s,t]/η_dis,   0 ≤ e[s,t] ≤ E_s
     e[s,T] ≥ e[s,0]   (시작 저장량은 spec.yaml, 기본 50%)
```

- 경쟁 시장에서 가격 수용자들이 각자 이익을 최대화한 결과는 이 비용 최소화의 해와 같습니다(선형 모형). 그래서 M1에서는 장주기 자산의 이익 최대화를 따로 풀지 않습니다.
- 출력: p¹, ch¹, d¹, λ, 그리고 (사슬 구조이므로) 구역 순위치로 계산한 **암묵적 경계 조류** f¹(l, t)

### 2.3 2단계: 재급전 (1단계 계획 고정)

조정 변수: 발전기 상향 u[g,t] ≥ 0, 하향 w[g,t] ≥ 0 (p¹ + u − w ∈ [0, cap·avail]).

```
min  Σ_t Σ_g c_g · (u[g,t] − w[g,t])  +  VoLL · Σ shed
s.t. 구역 수지:  Σ_{g∈z}(p¹+u−w) + Σ_{s∈z}(d − ch) + (들어오는 조류 − 나가는 조류) + shed = D[z,t]
     |f[l,t]| ≤ F_l
```

- **(i) 발전기만**: 저장은 1단계 그대로(ch = ch¹, d = d¹).
- **(ii) 저장도 시간을 넘어**: ch, d, e를 변수로 두고 2.2의 저장 제약을 1년 전체에 걸어 다시 고릅니다.
- **(iii) W1 북쪽 장주기만 고정**: 북쪽 구역(T3 정의)의 Window 1 잠정 사업만 1단계 계획에 묶고, 나머지 저장(FES 배터리, 기존 양수, 남쪽 W1 사업)과 발전기는 (ii)처럼 시간을 넘어 조정합니다. "NESO가 W1 북쪽 장주기만은 재급전할 수 없다"고 둔 판이라, **W1 북쪽 장주기 자체가 만드는 왜곡의 상한**입니다. (i)의 왜곡에는 다른 저장의 몫이 섞이므로, go/no-go 주 지표는 (iii)으로 계산합니다(04 보고서 3장).
- 실행 가능 집합이 포개지므로 **C(S6) ≤ C(S0,ii) ≤ C(S0,iii) ≤ C(S0,i)**가 항상 성립해야 합니다(시험).
- 재급전 비용 = 목적함수 값(비용 기준). 실제 BM 단가(입찰 행태 포함)보다 낮을 수 있으므로 결과는 **하한**으로 해석합니다.
- **중요한 성질 (구현 전에 알아 둘 것)**: (ii)는 모든 자원을 1년 전체에 걸쳐 비용 최소로 다시 고르므로, 최종 운전이 계획자 최적(2.4)과 같아집니다. 따라서 **(ii)의 계통 총비용은 항상 S6과 같고, 계통 총비용 기준 왜곡은 구성상 0**입니다. (ii)가 의미 있는 것은 **소비자 지급**(누구에게 얼마를 주는가)입니다. 시험으로 이 등식을 확인합니다. 계통 총비용 왜곡의 범위는 [0, (i)]이고, 현실적인 값은 M3의 순차 재급전이 줍니다.
- **나중에 붙일 순차 재급전(M3)을 위한 설계**: 재급전 함수의 인터페이스를 `redispatch(plan, network, mode, fixed_units=None)`처럼 두고, mode ∈ {"gen_only", "intertemporal"}로 시작합니다. (iii)은 mode="intertemporal" + fixed_units=W1 북쪽 사업입니다. M3에서 "sequential"을 추가합니다. 기존 `gbess/engine/rolling_bm.py`(하루 전 계획 → 실시간 조정)의 구조를 참고합니다.

### 2.3a 1단계 해가 하나로 정해지지 않는 문제 (D_lo, D_hi)

구리판 1단계에서는 효율이 같은 북쪽·남쪽 저장이 같은 가격을 보므로, 누가 충방전할지를 풀이기가 임의로 고를 수 있습니다. 그러면 왜곡 D가 풀이기 선택에 따라 달라집니다(04 보고서 1장 3번). 그래서:
1. 1단계를 풀어 최적 비용 C₁*를 얻습니다.
2. 1단계 비용 ≤ C₁* × (1 + 10⁻⁶)를 제약으로 둔 채, 재급전 비용을 **최소화**하는 1단계 계획과 **최대화**하는 1단계 계획을 각각 구합니다. 실제로는 "1단계 계획 + 재급전"을 하나의 LP로 묶어 재급전 비용을 최소/최대화합니다(최대화는 재급전 단계 자체는 최소비용이어야 하므로 이중 최적화가 됩니다. 정확한 정식화가 어려우면 근사안(예: 북쪽 저장 방전량 최소/최대화로 두 극단 계획 생성)을 제안하고 연구자에게 묻습니다).
3. 두 판의 왜곡을 D_lo, D_hi로 보고하고, **판정에는 D_lo를 씁니다.**

### 2.4 계획자 최적 (S6)

2.2에 구역 수지와 경계 한도를 처음부터 넣고 한 번에 풉니다. 출력: 계통 총비용, 구역 가격(구역 수지의 쌍대).

### 2.5 지표

| 지표 | 정의 |

| E_bind | S0 1단계에서 B4 또는 B6가 제약된 시간(암묵적 조류 ≥ 한도)에 W1 북쪽 장주기가 순방전한 양(TWh) |

### 2.6 설계안

| 설계안 | 구현 |
| --- | --- |
| S0 현행 | 2.2 → 2.3 (i)·(ii) |
| S6 계획자 최적 | 2.4 |
| S1a 고정 한도 | 2.2에서 북쪽 구역(T3에서 정의)의 Window 1 지원 장주기에 ch ≤ X·Pch, d ≤ X·Pdis. 그 뒤 2.3 |
| S1b 제약 연동 한도 | ① S0의 1단계에서 f¹(l,t) ≥ β·F_l인 시간을 표시 ② 다시 푼 1단계에서 그 시간에 북쪽 지원 장주기의 d = 0 (충전은 허용) ③ 2.3. **표시는 한 번만 하고 다시 반복하지 않습니다**(사전등록한 규칙 그대로) |
| S5 지역 가격 | 1단계를 구역 시장으로(= 2.4와 같은 운전). 경쟁 선형 모형에서는 **계통 총비용이 S6과 같은 것이 정상**입니다(시험으로 확인). S5의 의미는 소비자 지급과 구역 가격 |

**연구 메모 (결과를 미리 정하는 것이 아님)**: 03 문서 6.3의 손계산 예제에서 왜곡은 북쪽 저장이 "덜 충전"해서 생겼습니다. S1a·S1b는 출력을 막는 설계라 이런 왜곡은 줄이지 못할 수 있습니다. 그런 결과가 나오면 버그가 아니라 결과일 수 있으니, 그대로 보고하고 연구자에게 알립니다. 새 설계안(예: 충전 의무)을 임의로 추가하지 않습니다.

  1. 판마다 실행 기록 `run.json`(git 커밋, spec.yaml 해시, 입력 파일 해시, 해 상태, 걸린 시간)을 남깁니다(07 문서 E7 관행).

### T8. 과거 연도 기본 점검 (M1-9, 검증 V1의 첫걸음)

- **목표**: 같은 구역망을 **2025년** 설비·기상·수요와 **NESO 관측 한도 시계열**로 풀어, 제약 규모가 실제와 같은 자릿수인지 봅니다(spec.yaml `validation.V1`, `order_check_band` 1/3~3).
- **고쳐도 되는 파일**: `gbess/system/backcast.py`, 결과 `results/system/backcast/`
- **비교 대상**: `data/raw/neso_sql/da_constraint_flows.parquet`(경계별 조류·한도), `constraint_breakdown_*.parquet`(일별 제약 비용·물량). 비교 지표와 통과 기준은 spec.yaml의 `validation.V1` 그대로.
- **자료 규칙 (04 보고서, 작업 세션이 원자료로 확인함)**
  - 하루 전 조류 자료는 **2024-04-22에 정의가 바뀝니다.** 그 전에는 조류가 한도에서 잘려 있어(조류 > 한도인 구간 0%) 제약 발생 비율을 잴 수 없습니다. **2024-05-01 이후 자료만 씁니다.**
  - 한도 ≤ 0 또는 ≥ 9999인 구간은 자리채움 값이라 뺍니다.
  - 그룹 대응: B6 = SCOTEX, B4 = SSE_SP(~2024-04-20) / SSE_SP2. 대안 북쪽 그룹 SSEN_S(B2), NKILGRMO·SSE_GRMO(B5). 출처는 04 보고서 2장.
  - 2025년 관측(1시간 기준): B6 제약 발생 비율 32.5%, B4 40.2%, B4·B6 중 큰 쪽 초과량 7.42 TWh, 열적 제약 비용 £1,831m.
- **끝났다는 기준**: V1 지표별 모형 vs 실제 표, 통과 여부, 오차 방향
- **멈추고 물어볼 지점**: 통과하지 못해도 모형을 임의로 보정하지 않습니다. 오차 방향과 가능한 원인을 보고하고 묻습니다.

### T9. M1 보고와 go/no-go 계산

- **목표**: spec.yaml의 `go_no_go` 규칙을 그대로 계산해 보고합니다.
- **할 일**: 규칙에 들어가는 값을 표로 내고, spec.yaml `go_no_go` 규칙대로 계산한 판정을 적습니다.
  - 먼저 **검산**(04 보고서 3장): C(S6) ≤ C(S0,ii) ≤ C(S0,iii) ≤ C(S0,i), |C(S5) − C(S6)| ≤ 10⁻⁶ × C(S6), C(S1a)·C(S1b) ≥ C(S6). 하나라도 어기면 버그로 보고하고 판정하지 않습니다.
  - 판정 (M = £25m/년, 연구자 결정)
    - **no-go**: 한도 ×1.0과 ×0.8 모두에서 D_lo < £25m
    - **go**: 한도 ×1.0에서 D_lo ≥ £75m, ×1.2에서도 D_lo ≥ £25m, E_bind > 0, S1a·S1b 중 하나 이상이 C(S0) − C(S1x) > 0
    - **조건부**: 그 밖. 순차 재급전 하나와 바람 많은 기상연도 하나를 더해 다시 판정
  - M1의 헤드라인은 점추정이 아니라 범위로 씁니다.
- **끝났다는 기준**: `docs/notes/m1_go_no_go_KO.md`
- **멈추고 물어볼 지점**: **판정은 연구자가 내립니다.** Claude Code는 규칙대로 계산한 값만 내고, 다음 단계(M2 / 재검토 / B·C안)를 선택지로 묻습니다. 중요한 판정이므로, 연구자가 원하면 작업한 세션이 아닌 별도 세션에게 코드와 결과만 주고 다시 판정하게 합니다(03 문서 5.3).
