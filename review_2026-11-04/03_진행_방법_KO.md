## 0. 전체 흐름

```
[1단계] 결정 전 준비 (약 1주)
   01 문서 읽기  →  사실 확인 작업  →  교수님 미팅 자료
        │
[2단계] 교수님 미팅 → D1~D4 결정
        │
[3단계] 나머지 결정 + 사전등록 (약 1주)
   D5~D20 결정  →  결정 기록표 채우기  →  사전등록 파일
        │
[4단계] 기존 파일 고치기 (2~3일)
   방향 문서(08) → 해설(09) → 상태(10, 11) → README → 인계 메모
        │
[5단계] M1 최소 결과 (약 3~5주)
   구역망·입력 → 2단계 모형 → 설계안 3개 → 결과표
        │

   M1 결과를 보고 A안을 계속할지, B·C안으로 옮길지
```

기간은 혼자 진행하는 기준의 대략적인 추정입니다. 자료 확보 상황에 따라 크게 달라질 수 있습니다.

[범위]

- 고치면 안 되는 파일: 그 밖의 전부. 특히 data/raw/, model/, results/layer1/

[끝났다는 기준] (6장의 해당 작업 기준을 그대로)

### 5.3 받은 결과 확인하기

- 숫자는 시험(`tests/`)과 손계산 예제로 확인합니다. 새 코드에는 손으로 답을 계산할 수 있는 작은 예제 시험이 반드시 있어야 합니다(기존 관행, 09 문서 머리말).
- 문서 수정은 git diff로 무엇이 바뀌었는지 직접 봅니다.
- 중요한 판단(go/no-go, 검증 통과 여부)은 따로 독립 세션에게 코드와 결과만 주고 다시 판정하게 하면, 작업한 세션이 자기 작업을 채점하는 문제를 피할 수 있습니다. 2026-10-29 독립 심사(11 문서)가 이 방식이었습니다.

### 6.3 손계산 예제 (M1-4~6의 시험으로 쓸 것)

구역 둘(북 N, 남 S), 경계 용량 100 MW, 두 구간(t1 바람 많음, t2 바람 없음)인 예입니다.

| | t1 | t2 |
| --- | --- | --- |
| N 풍력 (한계비용 0) | 300 MW | 0 |
| N 수요 | 50 MW | 50 MW |
| S 수요 | 200 MW | 200 MW |
| S 가스 (한계비용 £100/MWh, 충분히 큼) | — | — |
| N 장주기 저장 | 100 MW, 효율 100%, 비어 있음에서 시작 | |

각 구간은 1시간으로 둡니다. 효율이 100%라 가스로 충전해 가스를 대신하는 것은 손익이 0이므로, 저장은 남는 풍력으로만 충전한다고 둡니다(효율이 100%보다 조금이라도 낮으면 실제로 그렇게 됩니다).

- **계획자 최적 (S6)**
  - t1: N 풍력 300 중 50은 N 수요, 100은 경계로 남쪽, 100은 N 저장 충전, 50은 출력제한. S 가스 100.
  - t2: N 저장 100 방전 → N 수요 50 + 남쪽 50. S 가스 150.
  - 가스 합계 250 MWh → **£25,000.**
- **1단계 (전국 시장, 제약 없음)**
  - t1: 풍력 300이 전국 수요 250을 모두 채우고, 남는 50만 저장에 충전. 가스 0.
  - t2: 저장 50 방전, 가스 200.
  - 가스 합계 200 MWh → £20,000. 제약을 무시했으니 계획자보다 쌉니다.
  - 그런데 t1 경계 조류는 300 − 50(N 수요) − 50(충전) = **200 MW**로 한도 100을 넘습니다.
- **2단계 (재급전, 발전기만 조정)**
  - t1에 N 풍력을 100 줄이고(bid) S 가스를 100 늘립니다(offer). 재급전 비용 **£10,000.**
  - 현행(S0) 합계 = £20,000 + £10,000 = **£30,000.**
- **왜곡 비용 = S0 − S6 = £5,000.** 전국 가격은 북쪽에 바람이 남는다는 것을 모르기 때문에, 저장이 충전을 50만 했습니다. 계획자라면 경계에 막힌 풍력을 100만큼 담아 두었습니다. **A안이 재려는 왜곡이 바로 이것입니다.**

이 예에서 바로 드러나는 결정이 하나 있습니다. **2단계에서 NESO가 저장장치도 조정할 수 있나, 그리고 시간을 넘어(t1에 더 충전시키고 t2 운전을 바꾸는 식으로) 조정할 수 있나?** 할 수 있다고 두면 재급전이 계획자 최적에 가까워져 왜곡이 작게 나옵니다. 실제 BM은 30분 단위로 지시하므로 시간을 넘는 최적 조정은 하지 않습니다. 이 가정을 D10에서 정하고 spec.yaml에 적어야 합니다.

이 예제(발전기만 조정하는 판과, 저장도 조정하는 판)를 시험 코드에 숫자로 넣습니다. 기존 `tests/`의 관행과 같습니다.

### 6.4 모형 구현에 관한 메모

- **1단계는 "전국 단일 노드의 비용 최소화"로 푸는 것이 일반적입니다.** 경쟁 시장에서 가격 수용자들이 각자 이익을 최대화한 결과는, 선형 모형에서는 전체 비용을 최소화한 결과와 같기 때문입니다. cap-and-floor의 꺾인 목적함수(D11 b)는 이 등가를 깨므로 M1에서는 넣지 않고, M3에서 장주기 자산만 따로 이익 최대화하는 방식으로 추가합니다.
- **2단계는 1단계 계획을 고정하고, 위아래 조정량을 변수로 둔 최소비용 문제**입니다. 조정 단가는 M1에서는 한계비용 기준(01 6.7, 02 D10)입니다.
- **풀이기**: 기존 엔진이 쓰는 풀이기(HiGHS, 07 문서 T11)를 그대로 씁니다.
- **PyPSA-GB를 쓸지**: M1은 자료만 PyPSA-GB에서 가져오고 모형은 작게 직접 만드는 방법이 빠르고 투명할 수 있습니다. PyPSA 전체를 쓰면 기능은 많지만 2단계 구조를 직접 짜 넣어야 합니다. C3 결과를 보고 D9에서 정합니다.
- **기존 엔진과의 관계**: 기존 `gbess/engine/`은 관측 가격을 받는 가격 수용자 모형이라, 구조층 1단계와는 다른 문제입니다. 기술 매개변수(`config/technologies.yaml`)와 비용(`config/costs.yaml`)은 그대로 씁니다.

### 6.5 M1 뒤 중간 점검 (go / no-go)

M1 결과표가 나오면 아래 기준으로 판단합니다. 기준은 M1을 돌리기 전에 spec.yaml에 숫자로 적어 둡니다.

| 결과 | 판단 | 다음 |
| --- | --- | --- |
| S0 − S6 (왜곡 비용)이 연간 수천만 £ 이상이고, 북쪽 장주기의 운전이 제약 시간대 조류를 늘리는 것이 보임 | **go** | M2 검증 → M3 확장 |
| 왜곡 비용이 작고(계통 총비용의 아주 작은 비율), 기본 점검(M1-9)의 오차가 그보다 큼 | **재검토** | 구역 수·경계 용량을 바꿔 한 번 더. 그래도 작으면 B안(포트폴리오 견고성)이나 C안(지속시간 요건)으로 무게를 옮김 |
| M1-9에서 과거 제약 규모가 자릿수부터 틀림 | **입력 재점검** | 경계 용량, 구역 배정, 풍력 시계열 확인 |

"연간 수천만 £"는 판단을 돕기 위한 예시입니다. 실제 기준은 연구자가 정합니다. 참고로 영국의 연간 제약 비용은 최근 수억~십억 £ 단위로 보도되지만, 이 연구에서 쓰기 전에 NESO 자료(C2)로 직접 확인해야 합니다.
